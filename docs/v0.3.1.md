# V0.3.1：可选 Seed、竞赛重启限制与 100×

本版改动设置、会话控制与统计。V0.3 的 DOPRI5 系数/容限、自适应步长、四体初始化算法、引力牢笼力、碰撞/潮汐/逃逸、Three.js 渲染与真实积分轨迹采样均保持原样。

## Seed 与比赛语义

- **随机模式默认开启**。每次打开页面、手动重置和自动换轮，以 Web Crypto 的 128 位新熵生成 Seed，并添加会话内递增后缀。已保存的固定 Seed 不会被当作随机启动输入。每轮实际 Seed 仍出现在设置、信息面板和事件里，可以复制到固定模式复现。
- **固定模式**保存用户输入的 1–80 字符 Seed。输入后“应用并重置”开始新比赛；普通“手动重置”重新从保存的根 Seed 开始。自动轮次沿用确定性序列 `String(hashSeed(previousSeed + ':next'))`，与固定 Seed 的旧序列兼容。
- **重新运行当前 Seed**将当前轮实际 Seed 作为新根，并恢复该轮实际使用的参考质量和尺度，再从第 0 年开始。尚未应用的质量/尺度草稿不会悄悄改变复现初态；按钮会同步这些设置。相同版本和相同物理配置才能比较后续轨迹。
- 切换模式在下一次手动重置生效，当前场不会中途换 Seed 策略。刷新页面是新比赛，不恢复之前的物理运行进度。

固定模式可取消“不限制”并设置 **Max Restarts**：0 只跑最初一轮，1 最多自动换轮一次，依此类推。存储为非负安全整数（最高 9007199254740991）；滑块常用范围 0–100，输入超过 100 时滑块范围随之扩展。随机模式不使用比赛次数限制。

引擎和主线程 Worker 故障恢复路径均检查次数，已排队的恢复定时器也会在执行时重新核查。物理解体及 Worker 故障后的自动换轮均消耗一次额度；手动重新开始清零本场额度、轮次、最长记录。原累计重置数和全局 generation 继续保留，保证尾迹隔轮清理兼容；旧熔断/冷却机制仍可在额度用完之前保护性停止。

达到额度后，最后的天体状态、原因、年份和事件保持可见，不再显示错误的重启倒计时。用户明确增大额度/选择不限制时可允许继续，手动开始新比赛也可继续。

信息面板新增当前 Seed、当前轮次、自动重启数、当前宇宙年份、最长单轮年份及其 Seed、最后结束原因。最长值包括当前仍在运行的轮次。统计与最多 200 条事件保留在本次页面会话，设置保存于原 localStorage schema；没有在线排行榜。

## 统一数值控件与质量排版

所有已实现的数值设置使用 `NumericSetting`：滑块 + 原生数字输入框共享同一个已验证值，支持键盘与精确输入。质量、速度、尺度、尾迹时间、全部牢笼数值及最大次数均使用该组件。

范围和精度来自 Registry 的 min/max/step，直接输入、Store 写入及持久化恢复均验证同样的步长；空值、NaN、Infinity、越界或超精度草稿不提交，显示提示，失焦或 Enter/Escape 恢复当前有效值。有效输入即时同步滑块并保存。无效旧存储字段回退该项默认值，其余有效设置保留。

原质量控件将标签和输出挤在同一行，范围轨道的通用 input 样式也不能用于数字框。本版标签独立一行，轨道、数字框和不换行的 M☉ 单位独立排布；数字框按步长显示质量两位小数、牢笼参数三位小数。输入参考质量不是当前恒星随机 ±3% 后的实际质量，原有“应用质量并重置”语义保持不变。尺度也仍在下一轮生效，牢笼、轨迹时间和速度仍即时生效。

## 100× 目标与实际倍速

Registry、持久化、引擎校验和 Worker 控制支持 0.1–100×，步长 0.1。1× 的天文换算仍为约 0.095 模拟年/真实秒。没有提高 DOPRI5 积分步长或放宽任何误差容限。

主线程仍最多一个未确认物理 tick；待计算积压最多 0.25 秒，Worker 每请求保持 1–4ms 软预算和 256 次尝试上限。过载丢弃推进积压，允许达不到目标；隐藏/暂停不补算。一次完整积分尝试、GC 或云主机调度仍可能超出软预算，不宣称硬实时。

UI 同时显示目标与近期实际倍速。实际值为已接受的物理时间 / 真实活跃时间 / 0.6，按约 1 秒时间常数平滑；Worker 请求另带未截断的活跃 wallElapsed，防止积压被丢掉后分母也缩短而虚报速度。暂停和结束显示 0，隐藏时间不算运行成本。

## 可重复验证

```bash
npm test
npm run typecheck
npm run build
npm run benchmark:speed
VITE_BASE_PATH=/1/ npm run build
VITE_BASE_PATH=/1/ PLAYWRIGHT_BASE_URL=http://127.0.0.1:4173/1/ npm run test:e2e
npm run format:check
```

Windows PowerShell 的环境变量请用 `$env:VITE_BASE_PATH='/1/'` 等语法。Linux 实测使用 `CHROMIUM_PATH=/usr/bin/chromium` 与 SwiftShader；CI 自动安装 Chromium。

- 102 项单元/组件测试覆盖随机启动/手动/自动换轮、固定根和序列复现、0/1/2 次限制、额度耗尽后等待不再启动、故障恢复额度及已排队恢复检查、最长轮统计、恢复实际初始参数、所有数值控件双向同步/校验/保存、终局提示、100× 精度及预算不足时的实际倍速。
- 完整 Playwright：13 项通过，2 项重复 WebGL 故障入口有意跳过；2520×1080、1920×1080、640×800 与动态缩放。新增用例验证真实 Worker、随机不同初态、固定精确复现、质量边界不遮挡、100× 运行、单请求背压、轨迹批次有界、重跑恢复未应用草稿和刷新恢复设置。
- 100× 下重复碰撞重启与 generation/尾迹清理由真实 Controller 集成测试覆盖；原潮汐、逃逸、近掠、自适应精度、历史采样及有界缓冲测试继续保留。

`benchmark:speed` 用 8 个不同 Seed，3× 默认牢笼，比较 1×/20×/100×，每轮观察 100 个物理年，共 24 轮。各倍速使用相同物理请求量 0.12 T₀（改变真实请求时长），不设墙钟预算；目的是验证数值等价性，不是证明硬件始终实时达到 100×。所有轮次到达观察上限，无数值失败；每个 Seed 的物理时间、最终天体状态和结束判据与 1× **逐值一致**，最大最终能量收支残差约 4.49×10⁻⁸、角动量误差约 1.10×10⁻¹⁰。四个额外 Seed 的接受步与逐批真实轨迹点亦有 20×/100× 完全一致测试。
